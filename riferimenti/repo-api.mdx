Quando devi collegare o fare debug su un'integrazione, il punto di partenza è il codice sorgente nei repository ufficiali. Questo indice ti permette di trovare subito il repo corretto senza dover cercare nella lista completa dei progetti, abbina ogni integrazione al suo repo e alla cartella rilevante in pochi secondi.

## Indice dei repository

| Integrazione | Area | Cosa contiene |
|---|---|---|
| KrossBooking | Client Kross / Gateway multi-tenant | Client Kross, gateway multi-tenant, endpoint scope |
| Gateway multi-tenant | Gateway MCP (`mcp.mattone.co`) | Proxy verso Kross / Shelly / Stripe |
| Conduit | Skill & API reference | Schemi endpoint, MCP Conduit |
| Shelly / SwitchBot | Smart lock & guest portal | MCP smart lock, guest portal check-in |
| Piattaforma | Bridge KB & provisioning | Bridge KB Notion→Conduit, provisioning studenti |

## Come usare questo indice

<Steps>
  <Step title="Identifica l'integrazione">
    Parti dal problema o dalla funzione che stai cercando: è un problema di disponibilità? Guarda KrossBooking. È una porta che non si apre? Guarda Shelly / SwitchBot.
  </Step>
  <Step title="Trova il repo nella tabella">
    Cerca la riga corrispondente all'integrazione e annota l'area funzionale indicata nella colonna **Area**.
  </Step>
  <Step title="Individua l'area funzionale giusta">
    Ogni area è organizzata in sezioni standard:
    - **Procedure operative**: runbook e note di manutenzione per il team
    - **Provisioning**: configurazioni per l'attivazione di nuovi studenti
    - **Tool MCP**: definizione dei custom tool collegati a Conduit
  </Step>
  <Step title="Consulta o segnala">
    Se trovi la risposta, aggiorna le note di onboarding o troubleshooting di conseguenza. Se trovi un bug, apri una segnalazione nel canale di riferimento.
  </Step>
</Steps>

<Note>
  I repo sono in sola lettura per i non-dev. Se trovi un bug o un'incongruenza, aprilo nel canale di riferimento Slack o nell'issue tracker, non modificare direttamente il codice sorgente.
</Note>
