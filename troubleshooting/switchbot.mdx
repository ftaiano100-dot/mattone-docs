<Warning>
Le serrature SwitchBot vanno in **standby**: lo status può dire `onlineStatus:"offline"` e `battery:0` **anche se la serratura è viva**. Un **comando** la sveglia via hub. Per questo il portale **prova sempre il comando** e non blocca sullo stato.
</Warning>

## Se l'apertura fallisce → leggi il CODICE
L'unlock ritorna `rawStatus` col codice reale (docs: SwitchBotAPI error codes):

| Codice | Significato | Cosa fare |
|---|---|---|
| `100` | ok | aperto ✓ |
| `161` | device offline | l'hub è vivo ma non raggiunge la serratura → vedi "Il caso 161" |
| `171` | hub offline | ricollega l'Hub Mini a corrente + WiFi **2.4GHz**, luce blu fissa |
| `190` | da ri-sincronizzare | apri una volta dall'app SwitchBot, poi riprova dal link |
| `160` | comando non supportato | verifica che il device sia una Lock/Lock Pro |
| `151/152` | device error/not found | controlla il `deviceId` registrato |
| `401` | token non valido | rigenera Token+Secret e aggiorna le env |

## Il caso 161 ("device offline") — il più frequente
`161` ≠ `171`: l'hub è **online** ma **non raggiunge quella serratura**. Ipotesi in ordine, dopo aver escluso la batteria:

<Steps>
  <Step title="OWNER o MEMBER? (causa #1)">L'API cloud comanda in modo affidabile **solo i device che l'account POSSIEDE**, non quelli **condivisi**. Se il token è di un account **membro** (non owner dell'Hub), lui apre dall'app ma la **nostra API torna 161**. **Fix:** Token/Secret dell'account **owner** della Home, o farsi promuovere **Administrator**.</Step>
  <Step title="Range / ostruzione Hub↔Lock (causa #2)">Serratura **entro ~5 m** dall'Hub; il Mini attraverso i muri fa ~3-4,5 m reali, metallo/TV/mobili lo azzerano. **Fix:** avvicina l'Hub alla porta. (Escluso se il cliente apre **da remoto**.)</Step>
  <Step title="Cloud Service off (causa #3)">Sulla serratura, nell'app, **"Cloud Service"** dev'essere attivo. **Fix:** riattivalo.</Step>
</Steps>

### Perché l'app apre ma il link no
L'app può aprire (a) via **Bluetooth diretto** se sei vicino, o (b) **da remoto** via cloud→Hub→lock. Il link usa **solo** (b) con le **nostre** credenziali. Quindi "da app apre" non smentisce il 161.

**Le due verifiche che chiudono il caso:**
1. *"La Home dell'Hub è tua (sei Admin) o ti è stata condivisa?"* → condivisa = **causa #1**.
2. *Test simultaneo:* il cliente apre da remoto (lontano) nello stesso minuto in cui provi tu l'API. Apre lui + tu 161 → **#1**. Falliscono entrambi (apre solo da vicino) → **#2**.

## Test senza aprire la porta
Manda `command:"lock"` (ri-blocca una porta già chiusa = innocuo) → `100` = il cloud raggiunge la lock; `161/171` = no.
